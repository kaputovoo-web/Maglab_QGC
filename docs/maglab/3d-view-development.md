# Maglab 三维地图开发方案

## 状态与目标

用户在设置汉化修复包装机后，要求开始三维地图开发：卫星影像、真实高程、地图细节、无人机模型与飞行轨迹，兼容 Android 遥控器及 Apple Silicon macOS。

本文是源码调研后的方案，不代表以下功能已实现或真机验收通过。当前 Android 3D 仍为默认关闭的实验功能。任何新模块不得改变未启用 Maglab overlay 的上游默认配置。

## 已确认的现状

- `Viewer3DTerrainTexture` 已经使用现有二维地图提供方，支持无 OSM 文件时，以载具 homePosition 周边约 500 米为半径加载影像。
- `Viewer3DTerrainGeometry::_buildTerrain()` 将地面顶点 z 固定为 0，不是真实起伏地形；现有网格密度主要跟随影像瓦片数量，不能直接满足地形采样需求。
- `Viewer3DTileQuery` 使用 RGBA32FPx4 拼接纹理，`Viewer3DTerrainTexture` 上传 RGBA32F。浮点纹理每像素 16 字节，内存开销明显高于 RGBA8 的 4 字节；目前瓦片数限制不能替代纹理尺寸、CPU/GPU 内存和并发预算。
- `Viewer3DVehicleItems.qml` 已有航点与任务连线；这与实际飞行轨迹是两个不同的数据层。
- `DroneModelDjiF450.qml` 已有姿态和桨叶动画，但高度来自 altitudeRelative。
- `Vehicle` 已公开 trajectoryPoints，可作为实际航迹接入的候选数据源；接入前需检查其高度数据、分段与重置语义。
- `TerrainAtCoordinateQuery` 提供异步高程查询，可复用现有 Copernicus 高程链路；现有查询接口不等于高吞吐地形瓦片引擎。
- `Viewer3DGeoCoordinateType` 当前使用 ENU 水平位置，但把 z 改写为输入 altitude；整个场景并未建立统一的绝对高程基准。
- OSM 建筑、影像、DEM 是独立数据源，不能用一个“地图提供方”设置混为一谈。

## 第一阶段实施记录：影像纹理存储

已将 `Viewer3DTileQuery` 的拼接与瓦片解码统一为 `QImage::Format_RGBA8888`，并将 `Viewer3DTerrainTexture` 的上传格式配对改为 `QQuick3DTextureData::RGBA8`。去掉了影像解码中不必要的 QPixmap 中转。此处保留原材质/着色器行为，不宣称已经完成色彩空间校准。

同尺寸影像的原始像素存储由每像素 16 字节降为 4 字节，减少 75%；例如 4096×4096 单份像素由 256 MiB 降为 64 MiB。这只是像素数据计算，不是进程峰值内存测量，也不包含解码、复制和驱动资源开销。尚未新增纹理边长、总像素和请求并发限制，长条大范围区域仍有超限风险。

新增 `Viewer3DTileQueryTest::_testTileComposition`，检查两瓦片画布字节数、瓦片偏移、缺失瓦片灰底以及 RGBA 原始通道顺序。现有桌面和 Android 构建均关闭测试，因此该新增单元测试尚未编译运行，不计作测试通过。

Android arm64 增量构建成功（`build-icon-zh.exit=0`，Gradle BUILD SUCCESSFUL）；当前为未签名构建产物，没有替换此前已签名的设置汉化包，也没有安装到遥控器。`git diff --check` 通过。全文件 clang-format 检查未通过，包含现存文件格式不符合当前配置的问题；没有为通过检查而全文件重排。完整 lint、桌面构建与真机渲染尚未验证。

## 第一阶段实施记录：区域/地图切换请求隔离

`Viewer3DTerrainTexture::loadTexture()` 现在在每次重载时立即断开旧查询到纹理对象的连接，安排旧查询延迟删除，并创建独立的新查询。即使新区域无可加载数据，也先取消旧查询的结果接入，避免旧区域影像覆盖新场景。这不是完整的瓦片调度器：单次查询内部缩放回退、网络并发和资源预算仍需后续处理。

新增 `_testReloadIgnoresPreviousQuery`，模拟旧查询在切换区域后发出完成与几何信号，断言新区域状态不被覆盖。测试尚未编译运行（现有构建关闭测试）；Android arm64 本轮增量构建成功，diff 空白检查通过。尚未签名安装或真机回归。

## 选型

### 第一阶段：原生局部三维地形

继续使用 Qt Quick 3D，不在 Android 内嵌 CesiumJS/WebView，也不立即引入完整 Cesium Native 渲染集成。原因是现有原生场景、姿态模型、地图接口已经可复用，能逐步控制内存和降级行为；此选择不是对具体遥控器 GPU 性能的保证。

数据层分离：

| 数据层 | 首选接入 | 注意事项 |
| --- | --- | --- |
| 卫星影像 | 复用现有天地图接口，允许使用现有其他授权影像源 | 需要用户自己的有效 Key；先验证国内网络和目标地区覆盖，不抓取绕过鉴权，不移除来源署名 |
| 地表高程 | 第一版复用现有 Copernicus 高程查询与缓存能力 | 验证服务可用性、实际数据分辨率、高程基准和请求限制；它不是建筑高度或避障数据 |
| 建筑 | 保留现有 OSM 建筑挤出 | 覆盖与高度依赖数据质量，不能保证所有建筑准确 |
| 无人机 | 先保留现有 F450 模型和姿态，后增加自带 glTF 2.0/GLB 资产导入 | 使用 Qt Quick 3D 适用的资产导入工具，运行时导入需单独验证；不声称任意 GLB 已可直接加载 |
| 任务线 | 现有任务数据 | 正确区分任务高度框架及地形相对高度 |
| 实际航迹 | 复用 Vehicle 航迹源，必要时补存绝对高程 | 必须支持多机、失联断段、清空和长度限制 |

天地图 Key 配置继续使用已有 Fact；任何新增开关、精度或预算设置也必须通过 Fact System。不得在仓库或 APK 中硬编码私人密钥。现有其他影像提供方可用性及商业授权需分别确认。

### 第二阶段：外部实景数据

对外部倾斜摄影/城市实景模型，选择 **OGC 3D Tiles** 作为未来交换与分块加载方向，glTF/GLB 作为模型内容格式。不是把单个超大 OBJ/GLB 整体装入内存。

完整 3D Tiles 需要 tileset 层级解析、坐标变换、包围体裁剪、屏幕空间误差 LOD、请求调度、缓存和 GPU 资源回收，不能只解析 tileset.json 就宣称支持。Cesium Native 可作为后续评估对象，但与 Qt Quick 3D 的渲染、线程、材质适配及 Android 资源预算仍有显著集成成本。

第一阶段不承诺已支持 3D Tiles、Cesium ion、Google Photorealistic 3D Tiles、OSGB 或全地球浏览。若用户提供自己的实景数据，先检查格式、坐标系、授权与大小，再决定转换管线。卫星影像叠加 DEM 产生地形起伏，并不会生成建筑立面纹理。

## 实施顺序与阶段验收

### A. 移动端资源预算与生命周期

1. 配对调整影像拼接和纹理上传格式为 RGBA8，验证通道、透明度、色彩空间与渲染输出，不只改其中一端。
2. 同时限制纹理边长、总像素、并发请求和缓存内存；根据渲染设备能力约束纹理大小。瓦片数量不能保证长条区域不超纹理边长。
3. 为切换地图、活动载具、参考点及退出场景建立请求代际标记或取消机制，防止旧请求结果覆盖新场景。
4. 提供无影像、无高程、网络失败状态；数据缺失时不能伪造为有效零高程。

验收：重复开关场景、切换地图与载具，不崩溃、无明显持续内存增长；失败有可理解的中文状态。记录机型、渲染后端、纹理尺寸和实际内存，不能仅依据启动成功判断性能。

### B. 统一坐标与真实地形

1. 明确局部原点（WGS84 经纬度和已知高程）、高程来源及垂直基准。DEM 与飞控 AMSL 不能不经验证就假设采用相同大地水准面；涉及椭球高与正常/正高时必须转换。
2. 在局部三维场景使用一致的米制坐标，收敛当前乘 10 的历史显示尺度。地形、无人机、航迹、航点、建筑均从同一个参考系转换。
3. 地形网格采样密度独立于影像瓦片数量，异步查询 DEM，检查样本数、有限值和 NoData；建立有界缓存。
4. 影像按 Web Mercator 投影生成 UV，不能简单按纬度线性插值后假设与瓦片像素完全对应。覆盖边缘和反经线/极区需明确限制或实现。
5. 无高程时明确提示降级为平面；有高程后更新法线、包围盒。参考点改变时，所有图层一起更新。
6. 场景范围先限定为局部飞行区域，再实现分块 LOD 和跟随移动的加载窗口，不先承诺无限范围高精度地球。

验收：以已知地形和飞控遥测对照，检查海拔、相对高度、负高程与失效数据；坡面连续、纹理不明显错位，无跨参考点跳变。地形显示不得用于替代飞控避障或安全离地高度判断。

### C. 无人机与轨迹

1. 保留现有模型的实时航向/俯仰/横滚，先校正坐标轴、比例与高度，再做外观替换；所有 Vehicle 指针先检查有效性。
2. 分开显示任务航线和实际航迹。实际航迹增加距离/时间抽样、有限点数与断线分段，不跨越失联位置直接画直线。
3. 验证起飞点与参考点海拔差、重连、返航、切换载具、多机和清空轨迹。
4. 航点的内部类型使用命令/稳定标识，不能依赖翻译后的 L/T/W/R 标签作逻辑判断。现有 Viewer3DVehicleItems 中有此风险，实施时应修复并回归任务显示。
5. 增加跟随、自由浏览与一键复位，避免遥测更新持续抢占用户手动镜头。

验收：SITL/回放先测，再在安全条件下真机核对，确认不同语言下任务连线一致。第一版模型外观不代表载具真实尺寸，不将视觉间距当成安全距离。

### D. 数据源与实景扩展

完成基础地形性能验收后，再增加离线 DEM/影像或 3D Tiles 适配器。每种格式都有明确的读取器边界、数据基准和错误报告，不把尚未实现的格式放进可用选项。

## 异步高程查询原型（未启用到 QML）

新增 C++ 显式调用入口 `requestElevationData(referenceElevation)`，复用 `TerrainAtCoordinateQuery`（其内部使用现有 TerrainOfflineQuery/地形瓦片缓存与下载链路，并非新增直连在线 API）。按当前网格逐点采样，每方向最多 32 个单元、共最多 1089 点，收到结果后验证数量、有限值和合理地表高程范围，再更新网格。调用者必须提供与 DEM 相同垂直基准的参考高程。该数量上限只是查询原型预算，不是完整的异步吞吐/缓存方案。
